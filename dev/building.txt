SecureOS — Building Apps Inside the OS
======================================

This folder (/apps/dev) holds the on-device developer sample content.

  Files here (currently staged on main):
    cc.bin                     TinyCC-based compiler driver (guest run unverified).
    hello.c                     Canonical validation sample source.
    pixels.c                    Small in-guest graphics sample.
    building.txt                This on-device quick-start guide.
    include/osapi.h             8.3 alias for public SecureOS API header.
    include/osabi.h             8.3 alias for public ABI version header.
    include/sofpack/sofpack.h   Public SOF packer header for in-OS builds.
    include/manifest/manifest.h 8.3-safe staged alias of manifestgen's public header.
    include/stddef.h           Freestanding clib size definitions.
    include/stdarg.h           Freestanding clib variadic arguments.
    include/stdint.h           Freestanding clib integer types.
    include/stdio.h            Freestanding clib file and console I/O.
    include/string.h           Freestanding clib string functions.
    include/stdlib.h           Freestanding clib numeric utilities.
    include/errno.h            Freestanding clib error codes.
    include/ctype.h            Freestanding clib character functions.
    include/limits.h           Freestanding integer bounds.
    include/stdbool.h          Freestanding Boolean definitions.
    lib/README.md               Notes on the staged compiler libraries.
    lib/libclib.a               Freestanding libc archive (required by disk build).
    lib/sofpack.a               8.3 alias for host libsofpack.a (required).
    lib/mangen.a                8.3 alias for host libmanifestgen.a (required).
    tcc/README.md               Notes on the TinyCC runtime helper archive.
    tcc/libtcc1.a               TinyCC runtime helper archive (required).

Only the headers listed above ship in this SDK. A clean disk build requires
all listed archives and cc.bin; guest compilation and execution remain
unverified (#766/#767/#768).

QUICK START (experimental — gated on #766/#767/#768)
----------------------------------------------------
  This is a target workflow, not a passing demo recipe. #766, #767 and #768
  remain open: guest compilation/launch lacks a real gate and the current
  manifest sidecar uses a name longer than the filesystem's 8.3 limit.
  Do not rely on cc to preserve an earlier output on failure.

  1. Attempt to compile the sample using the actual console command:
         run /apps/dev/cc.bin /apps/dev/hello.c -o /apps/hello.bin
  2. If it succeeds, request launch and approve unsigned execution:
         run /apps/hello.bin
  3. Intended output:
         hello from inside SecureOS

WRITING YOUR OWN APP (experimental — gated on #766/#767/#768)
--------------------------------------------------------------
  - Every app defines `int main(void)` (or `int main(int argc, char **argv)`).
  - Include the public API:  #include "osapi.h"
  - Print with:              os_console_write("...");
  - Return 0 from main on success; the value becomes the shell's $? .

EDITING SOURCES INSIDE THE OS (available now)
---------------------------------------------
  Run the line editor from the console:  run /apps/edit
  Commands (one per line; reading a file and saving each ask for your
  consent, and a denied save never changes what is on disk):
    ?        show help
    o <file> open an existing file, or start a new one (8.3 name, e.g. demo.c)
    p        print every buffered line
    a        append lines; end with a single dot "."
    c <n>    replace line n (type the new line when prompted)
    d <n>    delete line n
    w        save to the open file
    q        quit (unsaved changes are discarded, nothing is written)
  Limits: a typed line longer than 63 bytes is refused with
  EDIT:ERR:LINE_LONG and the buffer is left exactly as it was (nothing
  is truncated into your file); the editor also holds at most 32 lines.


  Example (mini.c):
      #include "osapi.h"
      int main(void) {
          os_console_write("my first app\n");
          return 0;
      }

  Build and run (experimental while gates are open):
      run /apps/dev/cc.bin /apps/dev/mini.c -o /apps/mini.bin
      run /apps/mini.bin  (approve unsigned execution)

  Edit it with: run /apps/edit (open /apps/dev/pixels.c, then save).
  Once the compiler and graphical acceptance gates land, build it with
  cc /apps/dev/pixels.c -o /apps/pixels.bin, then run /apps/pixels.bin

  source is staged but guest compilation and execution remain unverified.

FILESYSTEM NAME LIMITS (important)
----------------------------------
  The SecureOS filesystem uses 8.3 names: at most 8 characters for the name
  and 3 for the extension. So:
      hello.c      OK
      mini.c       OK
      myutil.c     OK
      hello_world.c   TOO LONG  -> use hello.c
  Output binaries use the .bin extension (the OS wraps your compiled ELF in a
  signed-container format automatically).

TRUST / SIGNING
---------------
  Apps built inside the OS are NOT signed by the SecureOS master key (that
  private key never lives on the device). When you run a locally built app the
  system will prompt you to allow an unsigned binary the first time. Choose
  "Allow" to run it once, or "Always" to remember your choice for that binary.

  Audit trail: both allow and deny decisions are recorded as launch.granted /
  launch.denied events (see #554 for owner-kind audit-surface tracking).
